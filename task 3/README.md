# Task 3 - Playwright Automation for Distributions and Transactions

This task uses Playwright Test as the test runner and validates records in the SQLite database:

- `resources/distribution_qa (1).db`

## Setup

From `task 3`:

```bash
npm install
npx playwright install
```

## Coverage

The suite implements the requested checks for a selected period (`YYYY-MM`).

1. All rows in `Distributions` are `COMPLETED`.
2. All rows in `Transactions` are `APPROVED` (period derived from `transaction_date` as `YYYY-MM`).
3. No `COMPLETED` distribution exists without an `APPROVED` transaction.
4. Every client in `Distributions` exists in `Transactions` for the same distribution/client linkage.
5. No `COMPLETED` distribution has `REJECTED` transaction status.
6. No `COMPLETED` distribution has `PENDING` transaction status.

Additional mocked status-check flow coverage:

7. Missing distribution period for an existing client returns not-found error.
8. Invalid client ID format returns validation error (Letter+Number, for example `C101`).

## Test Inventory (Test 1 - Test 8)

## Period Selection

- Default period: latest `YYYY-MM` found in `Transactions.transaction_date`.
- For distribution-based checks (Tests 1, 3, 4, 5, 6): latest `Distributions.period`.
- For transaction-based check (Test 2): latest `YYYY-MM` from `Transactions.transaction_date`.
- Manual base period (`TEST_PERIOD`) behavior:
  - `distributionPeriod = TEST_PERIOD`
  - `transactionPeriod = next month of TEST_PERIOD`
- Manual distribution-only override (`DISTRIBUTION_PERIOD`) behavior:
  - `distributionPeriod = DISTRIBUTION_PERIOD`
  - `transactionPeriod = next month of DISTRIBUTION_PERIOD` (unless explicitly overridden)
- Override individually: set `DISTRIBUTION_PERIOD` and/or `TRANSACTION_PERIOD`.

Examples:

- PowerShell:
  - `$env:TEST_PERIOD='2026-05'; npm test`
  - `$env:DISTRIBUTION_PERIOD='2026-06'; $env:TRANSACTION_PERIOD='2026-07'; npm test`
- Bash:
  - `TEST_PERIOD=2026-05 npm test`
  - `DISTRIBUTION_PERIOD=2026-06 TRANSACTION_PERIOD=2026-07 npm test`

Example mapping:

- If distribution period is set to `2026-06` and no transaction period is provided, transaction checks run against `2026-07`.

## Run

```bash
npm test
```

Run with a manual base period (transaction period auto-shifts to next month):

```bash
npm run test:period -- 2026-06
```

Each run prints a period summary in console for easier reference:

- distribution period used
- transaction period used
- total distributed amount + row count for the selected distribution period
- total transaction amount + row count for the selected transaction period

Run only the mocked status-check flow regression slice:

```bash
npx playwright test tests/status-check-flow.mocked.spec.js
```

HTML report is generated by Playwright after runs.
